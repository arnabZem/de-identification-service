# De-identification Service

A small Node.js / TypeScript / Express service that finds common PII in free-form text with regular expressions and rule-based validation, and replaces it with entity placeholders (`[EMAIL]`, `[PHONE]`, ...).

Text is processed in memory only. Nothing is sent to external services, stored, or logged.

> **Not an anonymization guarantee.** Names are detected only after an explicit label (`Patient Name: John Doe`); unlabeled names (`Patient John Doe`), street addresses and any other PII are **not** detected. Rules favor recall (a missed value is worse than a harmless over-redaction), so false positives do occur. See [Known limitations](#known-limitations).

## Quick start

Requires Node.js 24 (`nvm use` reads `.nvmrc`).

```bash
npm install
npm test            # unit + API tests
npm run test:cov    # with coverage (threshold: 90%)
npm run dev         # watch mode on http://localhost:3000
npm run build && npm start   # compiled build
```

### Configuration

All settings are environment variables, defined in `src/config/config.ts`. Invalid values stop the service at startup. `npm run dev` and `npm start` also read a `.env` file if present (Node's built-in `--env-file-if-exists`; real environment variables win): `cp .env.example .env`. The example enables the sample rules in `src/rules/custom-rules.json`. Tests ignore `.env`.

| Variable | Default | Meaning |
|---|---|---|
| `PORT` | `3000` | Listen port (1-65535) |
| `MAX_BODY_BYTES` | `1048576` | Max request body; larger requests get `413` |
| `SHUTDOWN_TIMEOUT_MS` | `10000` | Max wait for in-flight requests on `SIGTERM`/`SIGINT` |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn` or `error` |
| `CUSTOM_RULES_FILE` | unset | Path to a JSON file of [custom rules](#custom-rules) |

## API

### `POST /deidentify`

`Content-Type: application/json`

| Field | Type | Notes |
|---|---|---|
| `text` | string, required | Empty and whitespace-only text are returned unchanged |
| `entities` | string[], optional | Subset of `EMAIL`, `PHONE`, `SSN`, `DATE_OF_BIRTH`, `CREDIT_CARD`, `IP_ADDRESS`, `NAME`. Omitted = all. Must be non-empty if present. Duplicates are ignored. |

```bash
curl -s localhost:3000/deidentify -H 'content-type: application/json' -d '{
  "text": "Patient John Doe can be contacted at john.doe@example.com or +1-415-555-0134. DOB: 1990-05-12."
}'
```

```json
{
  "deidentifiedText": "Patient John Doe can be contacted at [EMAIL] or [PHONE]. DOB: [DATE_OF_BIRTH].",
  "entitiesDetected": { "EMAIL": 1, "PHONE": 1, "DATE_OF_BIRTH": 1 }
}
```

Selecting entities:

```bash
curl -s localhost:3000/deidentify -H 'content-type: application/json' \
  -d '{"text":"Contact john.doe@example.com at +1-415-555-0134","entities":["EMAIL","PHONE"]}'
# {"deidentifiedText":"Contact [EMAIL] at [PHONE]","entitiesDetected":{"EMAIL":1,"PHONE":1}}
```

- `entitiesDetected` lists only types with at least one replacement. Counts are per occurrence, not per unique value.
- Offsets and matched values are never returned.
- Types you do not select are left untouched, even where they overlap a selected type (see [Design decisions](#design-decisions)).

### `POST /deidentify/batch`

Same rules for many texts in one request. `texts` is a non-empty array of strings; `entities` works as above and applies to every text. Results are returned in input order, each in the single-text response shape. The whole batch shares the `MAX_BODY_BYTES` limit.

```bash
curl -s localhost:3000/deidentify/batch -H 'content-type: application/json'   -d '{"texts":["Patient Name: Jane Roe","call +1-415-555-0134"]}'
# {"results":[{"deidentifiedText":"Patient Name: [NAME]","entitiesDetected":{"NAME":1}},
#             {"deidentifiedText":"call [PHONE]","entitiesDetected":{"PHONE":1}}]}
```

### `GET /health`

Returns `200 {"status":"ok"}`.

### Errors

All errors share one shape: `{ "error": { "status": <number>, "message": <string> } }`. Messages are static and never contain request content.

| Status | When |
|---|---|
| 400 | Malformed JSON; `text` missing or not a string; `texts` (batch) not a non-empty array of strings; `entities` not a non-empty array of known types |
| 404 | Unknown route |
| 413 | Body larger than `MAX_BODY_BYTES` |
| 415 | `Content-Type` is not JSON |
| 500 | Unexpected failure (details only in server logs) |

Every response carries an `X-Request-Id` header, generated by the server and matching the log line for that request.

## Detection rules

Rules never match across line breaks, and none match inside a longer run of digits.

| Entity | Detects | Does not detect |
|---|---|---|
| `EMAIL` | `local@domain.tld`, including Unicode letters (`josé@exämple.com`, `пользователь@пример.рф`). Local part allows `._%+-`. Domain needs a dot and a TLD of 2+ letters. | `john@localhost`, `a@b`, quoted local parts, IP-literal domains |
| `PHONE` | `+<country code>` followed by 8-15 digits total (`+44 20 7946 0958`, `+14155550134`). US/NANP: `415-555-0134`, `(415) 555-0134`, `415.555.0134`, `415 555 0134`, `4155550134`, `14155550134`, with optional `1` / `+1`. | 7-digit local numbers (`555-0134`), non-US numbers without `+`, NANP numbers whose area code or exchange starts with 0 or 1, extensions |
| `SSN` | `123-45-6789` (format-only), plus `123 45 6789` and `123456789` when valid (area not `000`/`666`/`900-999`, group not `00`, serial not `0000`) | Anything else |
| `DATE_OF_BIRTH` | A date after a label (`DOB`, `D.O.B.`, `date of birth`, `birth date`, `birthdate`; case-insensitive; optional `:`, `-` or `is`) on the same line. Only the date is replaced; the label stays. Dates: `1990-05-12`, `1990/05/12`, `05/12/1990`, `12/05/1990`, `12.05.1990`, `May 12, 1990`, `12 May 1990`. | Dates without a label, 2-digit years, impossible dates (`1990-02-31`), years outside 1900-2099, ordinals (`May 12th`) |
| `CREDIT_CARD` | 13-19 digits passing the Luhn check, as bare digits, `4-4-4-4` (plus an optional 1-3 digit tail), `4-6-5` or `4-6-4`, with one consistent space or hyphen separator | Luhn failures, other groupings, 20+ digit runs |
| `IP_ADDRESS` | IPv4 dotted quads, octets 0-255, no leading zeros. Private and loopback addresses are included. | IPv6, `256.1.1.1`, `01.2.3.4`, `1.2.3.4.5` |
| `NAME` | 1-5 capitalized words after a label (`Name`, `Patient`, or `Patient`/`Full`/`First`/`Middle`/`Last`/`Legal`/`Maiden` + `Name`; case-insensitive) and a colon, on the same line. Only the name is replaced. Handles initials (`John Q. Public`), `Doe, John`, titles, apostrophes, hyphens and Unicode. Stops at a lowercase word or the next label (`Name: John Doe, DOB: ...`). | Unlabeled names (`Patient John Doe`), labels without a colon, lowercase names |

### Custom rules

Extra entity types can be added without code changes. Set `CUSTOM_RULES_FILE` to a JSON array and restart:

```json
[
  { "entity": "MRN", "pattern": "MRN[: ]*(?<value>\\d{6,10})", "flags": "i" },
  { "entity": "EMPLOYEE_ID", "pattern": "\\bE\\d{5}\\b" }
]
```

- `entity`: `UPPER_SNAKE_CASE`, unique, and not a built-in name. It becomes the placeholder (`[MRN]`) and a valid value for `entities`.
- `pattern`: a JavaScript regular expression. If it has a named group `value` and that group matched, only the group is redacted; otherwise the whole match is. Empty matches are ignored.
- `flags` (optional): any JavaScript flags, such as `i` or `u`. `g`, `d` and `y` are managed by the service.
- Custom entities rank below all built-ins on equal-length overlaps, in file order. The longest span still wins.
- An invalid file, entry or pattern stops the service at startup.

> **Patterns are trusted configuration.** They are not checked for catastrophic backtracking, and nothing stops them matching across line breaks. A slow pattern blocks every request.

## Known limitations

General
- Names, addresses, and every other PII type are out of scope. `Patient John Doe` is intentionally left unchanged.
- Plain text only. Obfuscated values (`john [at] example [dot] com`), digits spelled out, non-ASCII digits, and values split by line breaks are not detected. JSON-escaped text must be decoded before sending.
- Input is never Unicode-normalized, so output outside matches is byte-identical to the input.

Per rule
- **EMAIL:** an ASCII-only or Unicode address with no dotted domain is not matched. Leading punctuation such as `-john@x.com` stays outside the redacted span. If a candidate's local part has no letters or digits, scanning restarts inside it, so `..@foo.bar@x.com` becomes `..@[EMAIL]`.
- **PHONE:** a bare 10-digit number that is NANP-valid is redacted even if it is an ID (for example `9876543210`). International numbers without `+` are missed. A `+` sequence of 8-15 digits separated by spaces is redacted even if it is not a phone number.
- **SSN:** the hyphenated form is not range-validated, so `000-12-3456` is redacted (deliberate, favors recall). Bare 9-digit IDs and ZIP+4 without a hyphen can be false positives.
- **DATE_OF_BIRTH:** day/month order is not interpreted; a numeric date is accepted if it is a real date in either order. Labels in other languages are not recognized.
- **CREDIT_CARD:** no issuer (IIN) check. Valid test numbers (`4111 1111 1111 1111`) are redacted. A grouped card followed directly by a CVV or expiry (`4111 1111 1111 1111 123`) is redacted as the card only; the trailing digits remain.
- **IP_ADDRESS:** version strings that look like IPv4 (`1.2.3.4`) are redacted.
- **NAME:** lowercase names (`Name: john doe`) and lowercase particles (`Ludwig van Beethoven` redacts only `Ludwig`) are missed, as are names past the fifth word. Any capitalized value after a matching label is redacted (`Company Name: Acme`).
- **Overlaps:** when two matches partially overlap, only the longer one is redacted and the rest of the shorter one can remain.
- **Custom rules:** regex only (no checksum or calendar validation), not checked for catastrophic backtracking, and loaded only at startup.

## Project structure

```
src/
  config/config.ts          settings from env (flat object)
  routes/index.ts           routes
  validators/               express-validator chains
  controllers/              thin HTTP adapters
  services/                 DeidentifyService: composes detect + replace
  views/                    response shaping
  models/                   contracts only (types)
  rules/                    one file per entity + registry (index.ts) + scan helper
  utils/detect.ts           rules -> non-overlapping spans
  utils/replace.ts          spans -> text + counts
  utils/logger.ts           compact logger
  errors/AppError.ts        status + message
  middleware/               request logger, error handler
  app.ts / server.ts        wiring / listen + graceful shutdown
test/                       mirrors src/, grouped into named suites
```

Adding an entity: add it to `ENTITY_TYPES` (`models/entity.ts`, order = overlap priority), add a rule file in `src/rules/`, register it in `src/rules/index.ts`, and add a spec. Detection and replacement code does not change. For regex-only entities, a [custom rules](#custom-rules) file needs no code change at all.

## Design decisions

- **Detection and replacement are independent.** `detect(text)` returns spans; `replace(text, spans)` returns text and counts. Neither imports the other and both depend only on the contracts in `models/`. `DeidentifyService` is the only place that calls both. `replace` can be tested with hand-built spans, and per-person tokens or reversible tokenization would change only `replace`.
- **Single-pass replacement over original offsets.** Sequential `.replace()` calls would shift offsets and could re-match placeholders. Output is rebuilt once, and text outside spans is copied untouched. This also makes the service idempotent: running it twice gives the same result.
- **Deterministic overlap resolution.** The longest span wins; ties go to the higher-priority entity (`CREDIT_CARD` > `SSN` > `DATE_OF_BIRTH` > `IP_ADDRESS` > `EMAIL` > `PHONE`). The result does not depend on rule order.
- **Detect everything, then filter.** All rules always run, and the caller's `entities` selection is applied afterwards. If only `PHONE` is selected, a credit card number is not partially replaced with phone fragments.
- **Validation where regex cannot decide.** Luhn for cards, calendar checks for dates, range checks for SSNs. Card grouping is limited to common layouts, because accepting any single-space grouping joined unrelated numbers (a phone and an SSN) into a fake card.
- **Linear-time regexes.** Quantifiers are bounded, separators are parsed in only one way, and lookbehinds anchor the start of matches. Every rule is tested against 1 MB adversarial inputs with a time budget.
- **No PII in logs or errors.** The request logger records method, path (no query), status, duration, text length and per-entity counts. Error messages are static, and library error messages are never forwarded (they can echo request content).
- **Errors from Node's own tables.** `AppError` defaults its message to `http.STATUS_CODES`, and body-parser errors already carry the correct status. The response uses a numeric `status` rather than a string code, because reason phrases can change between Node versions.
- **Trade-off: recall over precision.** For data going to an external AI system with no human review, a missed value is worse than an over-redaction.

## Potential improvements

- Safety checks for custom rule patterns (a timing probe or a safe-regex check), and reloading without a restart.
- IPv6, more national ID and phone formats, labels in other languages.
- Per-person tokens (`[EMAIL_1]`) or reversible tokenization, by replacing `replace`.
- Authentication, metrics and tracing, rate limiting, and a container image if this leaves an internal network.
